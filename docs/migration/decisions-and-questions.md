# Decisions and open questions

One list for everything the new app must decide. When a question is answered, move it to Decisions with the date and the reason, and update the rule it points to.

## Decisions

| ID | Decision | Reason | Rules | Date |
| --- | --- | --- | --- | --- |
| D-01 | Eligibility (average, age, gender) **warns** and lets the entry through. Legacy blocks it. The warning names the failed rule. | The registration site takes payment and does not check division rules, so we must accept what it sends. | `REG-04`, `REG-37`, `REG-15` | 2026-10-20 |
| D-02 | Legacy **defects** listed below are fixed, not copied, unless a question says otherwise. **Exception:** anything the registration site can see (paths, bodies, status codes, limits) stays as legacy until a vendor change is agreed (D-09). | Recording legacy as-is is for reference; copying crashes and data loss helps no one. | see table | 2026-10-20 |
| D-03 | **One registration (one division) per bowler per tournament.** Enforce in code. Adding a database constraint is a schema change; deferred to Q-26 (2026-10-22). | Owner confirmed. | `REG-01` | 2026-10-20 |
| D-04 | **No sweeper-only entries.** Every registration keeps at least one qualifying squad, on create **and** on update. | Owner confirmed. Legacy checks only on create; `PATCH` can remove every squad. | `REG-03`, `REG-31` | 2026-10-20 |
| D-05 | **Returning bowler: patch, not replace.** Only fields the request sends overwrite stored values. Missing fields (SSN, date of birth, gender) keep their stored values. Same for append. | Owner confirmed. Fixes the SSN-erasing defect. | `REG-07`, `REG-14`, `BWL-16a` | 2026-10-20 |
| D-06 | **A paid squad entry counts as an entry**, bowled or not. No-shows get zeros on completion, as in legacy. Prize spots are funded by paid entries. | `SQD-15`, `RES-02`, `REG-20` | 2026-10-20 |
| D-07 | **"Previous casher" flag stays as-is.** It marks an at-large advancer (or seeded finalist) who already received a cash payout on a squad. It is information for the director; the app does not change any amount. | Owner explained: finals ratio (say 1 in 7) is tighter than cash ratio (1 in 5), so a bowler can cash on a squad without advancing, then make the at-large. | `RES-16`, `RES-21` | 2026-10-20 |
| D-08 | **No advancers means exactly one casher**, even if the cash ratio allows more. Keep legacy. | Owner confirmed. | `RES-05` | 2026-10-20 |
| D-10 | **A complete squad or sweeper is locked.** No refunds, no removals, no score changes, no lane moves. A refund removal must happen before the squad is completed. The new **server** enforces this; legacy only locks the screens. | Owner confirmed. | `SQD-17`, `REG-20`, `REG-34`, `SCR-06` | 2026-10-20 |
| D-11 | **Refunds happen outside the app.** For our system, a refund is just deleting the squad registration (desk "remove from squad", or a site `PATCH` that drops the squad). No refund record is kept. | Owner confirmed. | `REG-20`, `REG-31`, D-06 | 2026-10-20 |
| D-12 | **Tournaments, divisions, squads, and sweepers can be edited** (legacy can only add them). Which fields, and when, is settled per feature as we build it. General rule: **a squad or sweeper with scores is locked from editing.** Editing a division's criteria after bowlers are registered shows a warning: the change is not retroactive, already-registered bowlers may no longer fit, and the director must review them by hand. | Owner decision. Details to discuss feature by feature. | `TRN-10`, `DIV-12`, `SQD-14` | 2026-10-20 |
| D-13 | **Super sweeper cash ratio must be at least 1.** | Owner decision. Stops the divide-by-zero crash. Note: other ratios must be **greater than** 1; with 1, every super sweeper bowler cashes. Existing rows may hold the legacy default 0. | `TRN-09`, `RES-28` | 2026-10-20 |
| D-14 | **Ties at the cut are settled by the tie-breakers, as in legacy.** The number who advance never grows because of a tie. The **cut line always divides** advancers (above) from non-advancers (below); the cash line works the same way. When the last spot above a line was won on a tie-breaker (equal total), the standings mark the bowlers on both sides of the line who share that total, and say which tie-breaker decided it. | Owner decision; legacy behavior confirmed in tests (`NoPreviousAdvancers_TieForLastAdvancer`). Owner was unsure whether all tied bowlers should advance; legacy does not do that. | `SCR-11`, `RES-07`, `RES-11` | 2026-10-20 |
| D-15 | **Tournaments, divisions, squads, and sweepers can be deleted.** When, and what happens to related data, is settled per feature in the same discussion as editing (D-12). | Owner decision. | `TRN-10`, `DIV-12`, `SQD-14` | 2026-10-20 |
| D-16 | **A full tie at a line** (equal on every tie-breaker) is flagged on the standings and the director picks. No extra automation. | Owner agreed; expected to be very rare. | `SCR-11`, D-14 | 2026-10-20 |
| D-17 | **Leave existing super sweeper cash ratios of 0 in the database.** Only saving is checked: a new or edited tournament must have at least 1 (D-13). Results for an old tournament with 0 must show a clear message instead of crashing. | Owner decision. The old value is invalid but historical. | `TRN-09`, `RES-28` | 2026-10-20 |
| D-18 | **Home (`/`) shows a card for the current tournament** (name, dates, center, links into it) and a link to all tournaments. If none is current, it shows the next upcoming one; if there is none, a short empty message. Home is not the tournament list, because bowlers and admin pages sit outside any tournament. | Owner decision. Legacy opened on the list because the desktop app needs a tournament first; on the web the URL carries the tournament. | `TRN-11` | 2026-10-21 |
| D-19 | **Hide, do not disable.** Tournament items exist only in the tournament menu, which shows only inside a tournament. Items the user lacks permission for are hidden (signed out, or wrong role). The API still enforces access. | Owner decision. Matches the 0.3.0 rule "no permission, no Add button". | `TRN-11` | 2026-10-21 |
| D-20 | **"Current" is decided by dates.** Current and upcoming = end date is today or later, soonest first. Past = end date before today, newest first. No stored flag, no schema change. The Home card is the first current or upcoming tournament. | Owner decision. Runs one tournament at a time (one per year). | `TRN-11` | 2026-10-21 |
| D-21 | **The tournament in context lives in the URL** (`/tournaments/{id}/…`). Two levels of navigation: a global menu, and a tournament menu that shows only when the URL names a tournament. In 0.2.0 only public read-only pages exist; the 0.2.0 list has no New button (it comes after 0.3.0, with auth). | Owner decision. Direct links and the back button work. | `TRN-10`, `TRN-11` | 2026-10-21 |
| D-22 | **Layout: top bar for the app, sidebar for the tournament, page header for the squad or sweeper.** The top bar holds global links on every page. The sidebar shows only inside a tournament and lists the tournament's pages. Inside a squad or sweeper, the sidebar does not change; the page header shows a breadcrumb, the name and status (Open or Complete), a "Complete" button, and tabs for that session's pages (lane assignments, scores, results). The sidebar grows as features ship; items for features not yet built do not appear (D-19). | Owner decision after comparing mockups. Each URL level gets one place on screen. | `TRN-11`, `SQD-15`, `SQD-16` | 2026-10-21 |
| D-23 | **Squads and sweepers use the same pattern:** a card list in the sidebar section "Squads" or "Sweepers", then the page header and tabs from D-22. **Super sweeper results are reached from the sweeper card list**, not from the sidebar's results group. An "Add squad" or "Add sweeper" button on the card list is designed when we build commands (0.4.0 and up). | Owner decision. Squads and sweepers are alike; the super sweeper spans the sweepers. | `SQD-*`, `RES-22` to `RES-29a` | 2026-10-21 |
| D-24 | **Each list row shows name, dates, bowling center, and entry fee.** The name links to the tournament overview page (`/tournaments/{id}`), which shows those same four fields read-only. Its sidebar holds only "Change tournament" until later features add items (D-19, D-22). Games and ratios appear on a page when a feature needs them (create, edit, results). | Owner decision. These are the fields the vendor routes return (`API-03`, `API-04`); no extra route is needed. | `TRN-11` | 2026-10-21 |
| D-25 | **The web app calls the vendor routes** `GET /v1/tournaments` and `GET /v1/tournaments/{id}`, with the shapes in `API-03` and `API-04` (D-09). `GET /v1/tournaments/{id}` returns 404 for an unknown id and 400 for an id that is not a UUID. Until divisions, squads, and sweepers ship, the detail response leaves out their arrays (an empty array would claim there are none); each feature adds its array. The vendor keeps using the legacy API until cutover, so this does not break them. | Owner decision. One route, one shape. | `TRN-11`, `API-03`, `API-04` | 2026-10-21 |
| D-26 | **The database is a separate run.** This slice builds the shell, Home, list, and overview on the repository interface with fixed, realistic demo data in the vendor shape. The next run adds the legacy database: Prisma on MariaDB, a Docker Compose service (D-30 to D-35), and D-03's constraint decision (deferred to Q-26). The list has no empty-state call to action until auth exists: it says "No tournaments yet." | Owner decision. Keeps this plan small and the UI real and testable. | `TRN-11` | 2026-10-21 |
| D-27 | **Every route declares its access, and undeclared routes deny** (the 0.2.0 release rule). This slice adds a small version: `createApp` takes each router with an access label; `public` is the only label until auth (0.3.0). Mounting a router without a label fails at startup. | Owner decision. Every later route starts with it. | `TRN-11`, `API-01` to `API-04` | 2026-10-21 |
| D-28 | **The web app groups and sorts the list, using the browser's local date for "today."** The API returns the full list with no filter or sort, as in `TRN-11`. | Dates are plain dates (no time zone); the director's own day is what counts. Testable with a fixed clock. | `TRN-11`, D-20 | 2026-10-21 |
| D-29 | **Keep the "Check API" button on Home until the API reads the production database.** Remove it then, because a working read proves the API and database connect. Removing the old `GET /tournaments` demo route breaks the live site for a short time between the API and web deploys; that is accepted because no one uses the site. | Owner decision. | `TRN-11` | 2026-10-21 |
| D-30 | **Prisma on MariaDB, schema written by hand, one model per slice.** `schema.prisma` models only the `Tournaments` table now and maps the typo column with `@map`. Hand-writing keeps unused tables out. | `TRN-11` | 2026-10-22 |
| D-31 | **A stored row that breaks the vendor shape is skipped and logged.** The list drops it and logs a warning with its id. `GET /v1/tournaments/{id}` for that id returns 500. | Owner decision. One old row must not hide the rest. | `TRN-11`, `API-03`, `API-04` | 2026-10-22 |
| D-32 | **A database outage gives 503 `{ message }`.** A new `GET /ready` pings the database and returns 503 while it is down. `/health` stays plain liveness, so an outage does not restart the app. | Owner decision. Follows `docs/api-standards.md`. | `TRN-11` | 2026-10-22 |
| D-33 | **`DATABASE_URL` is required.** The API fails at startup without it. Format: `mariadb://USER:PASSWORD@HOST:3306/DATABASE`. Production sets it as an App Service setting. No demo-data fallback. | Owner decision. Lost settings must not show fake tournaments. | `TRN-11` | 2026-10-22 |
| D-34 | **Local database: Docker Compose, `mariadb:11.4.7`, database `bowling_megabucks`, user `megabucks`.** The owner creates the local tables from `database.md`. `npm run db:seed` in `api/` adds sample rows. | Owner decision. 11.4.7 is the version the legacy repo pins in its compose file and tests. | `TRN-11` | 2026-10-22 |
| D-35 | **Repository tests use a real MariaDB 11.4.7 started by Testcontainers** (`@testcontainers/mariadb`), not Compose and not a mock. The tests create their own tables. | Owner decision. Proves the mapping (decimals, dates, `char(36)`) and needs no CI service. | `TRN-11` | 2026-10-22 |
| D-36 | **Reset the test database by truncating, not by restarting the container.** One container starts per test run (Vitest `globalSetup`); a helper truncates every table before each test. Stryker gets one database per worker, or skips the repository file; the plan decides. | Owner decision. Start-up costs seconds; a truncate costs milliseconds. | `TRN-11` | 2026-10-22 |
| D-37 | **Two routes list divisions.** `GET /v1/tournaments/{id}` gains a `divisions` array in the exact vendor shape (`API-04`: `id, name, minimumAge, maximumAge, minimumAverage, maximumAverage, gender`), as D-25 says. The vendor shape stays fixed (D-09) and the web app gets the fields it needs. | `DIV-12`, `API-04` | 2026-10-23 |
| D-38 | **Division `number` is unique per tournament.** `(TournamentId, Number)` is a candidate key. Legacy does not check it. Until then old rows may hold duplicates, and lists sort by `number`, then `name`. | Owner decision. Display order needs one answer. | D-39 | **A stored division that breaks the read shape is skipped and logged**, like tournaments (D-31). One old row must not hide the rest. | `DIV-12` | 2026-10-23 |
| D-40 | **Divisions page: a table at `/tournaments/{id}/divisions`,** one row per division (number, name, gender, ages, averages, handicap), reached from a "Divisions" link in the tournament sidebar.
