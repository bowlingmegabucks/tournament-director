# Add registration (desk)

Built on branch `createRegistration`. Migration source: [docs/migration/registrations.md](../migration/registrations.md), [bowlers.md](../migration/bowlers.md), and [payments.md](../migration/payments.md).

The desk adds a registration for a bowler already on file or for a new one, on the web page `/tournaments/{id}/registrations/new`. It is web only (D-157): the registration site keeps its own routes, in [registration-api.md](registration-api.md), and the vendor contract does not change (D-09). Both paths run the same checks and the same one-transaction save (`completeRegistration` in `api/src/features/registrations/register.ts`).

Needs `registrations.write` and `bowlers.read` (director and admin, D-157, D-97). The API key cannot reach these routes.

## What the desk does

1. **Find a bowler** by last name or first name (starts with), email, or USBC ID (`BWL-14`), or choose **New bowler**. A bowler already in this tournament carries a "Registered" badge with the division (D-159). The app matches no names (D-161): two Marias look alike, and the desk reads the USBC ID and town.
2. **Three steps:** Bowler, Registration, Review (D-164). Back and the progress list keep what was typed.
3. **A bowler registered in this tournament starts on Registration** with a notice, and the Bowler step is one click away and editable (D-165). Squads and sweepers already held show checked and locked.
4. **Review** shows each changed bowler field old against new, what the registration is, and **what to collect** (D-166). One button saves.
5. Success goes to the Registrations list with a toast.

Opened from a squad or sweeper lane page, the same page opens with that session checked and locked (`REG-22`, D-164).

## Fields

`POST /v1/tournaments/{id}/registrations` takes:

| Field              | Type               | Notes                                                                                                                         |
| ------------------ | ------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `divisionId`       | UUID               | Required. Must belong to the tournament                                                                                       |
| `average`          | integer or null    | 1 to 300; blank is null (`REG-16` words)                                                                                      |
| `squadIds`         | list of UUID       | New squads only. At least one counting the bowler's held squads (`REG-03`)                                                    |
| `sweeperIds`       | list of UUID       | New sweepers only                                                                                                             |
| `superSweeper`     | boolean            | Needs every sweeper (`REG-06`)                                                                                                |
| `bowlerId`         | UUID, optional     | A stored bowler. Then `bowler` is only what changed (D-05, D-158)                                                             |
| `bowler`           | object             | Flat text fields: names, street, city, state, zip, email, phone, USBC ID, birth date, gender (`Male`, `Female`, or blank)     |
| `appendToExisting` | boolean, optional  | The desk confirmed adding to the bowler's registration (D-159, D-165)                                                         |

A new bowler needs only first and last name, plus what the division asks for (D-162).

## API

| Route                                         | Request                | Response                                                                                       | Errors                                                                                                                                                                                                                                                  | Vendor-visible |
| --------------------------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `GET /v1/bowlers`                             | query: filters (above) | `200 { bowlers: [{ id, name, firstName, lastName, usbcId, city, state, registered }], more }`   | `400` no field or a bad tournament id; `401`; `403`                                                                                                                                                                                                       | No             |
| `GET /v1/bowlers/{id}?tournamentId=`          |                        | `200 { bowler, registration }` (registration is null when none)                                | `400` bad id; `401`; `403`; `404`                                                                                                                                                                                                                         | No             |
| `POST /v1/tournaments/{id}/registrations`     | body (Fields)          | `201 { registrationId, mode: 'created' or 'appended' }` and a `Location`                        | `400 { message, errors }` per field; `404` tournament or bowler; `409 alreadyRegistered { existing }`; `409 usbcIdOnFile { bowler }`; `409` complete tournament (`errors.form`); `401`; `403`; `503` database down                                         | No             |

The `GET` for the list on the same path keeps `registrations.read`. One path carries two access labels, one per method.

## Screens

Add registration page, the Registrations page link, and the lane page link, described above. The page is one column; the Review table is two columns and fits 320 px. Axe passes on every step and dialog in dark and light mode.

## Not built

Edit, delete, change division, and super sweeper add or remove on an existing registration (`REG-15` to `REG-19`, `REG-25`, Q-37) are the registrations edit feature. Recording real payments stays Q-17's proposed feature. A database constraint for one registration per bowler per tournament stays Q-26.
