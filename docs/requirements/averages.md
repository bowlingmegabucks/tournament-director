# Average verification

Built on branch `migrate-average-verification`. New feature with no legacy twin, so every rule has the prefix `AVG` and is marked "new". The plan lived in `docs/plans/average-verification.md`; decisions are D-287 to D-298 in [decisions-and-questions.md](../migration/decisions-and-questions.md).

A director checks the average each handicap bowler gave, one bowler at a time. **Verify** accepts the number. **Adjust** replaces it and records why. Handicap uses the checked number; until someone checks, the number the bowler gave stands and every screen that shows handicap marks the bowler "Average not verified".

Reading the Averages page needs `registrations.read`. Saving needs `averages.verify` (director and admin, D-292). The API key cannot reach these routes. A complete tournament is read only (D-130).

## What the director does

1. Opens **Averages** in the tournament menu (`/tournaments/{id}/averages`). The page lists registrations in handicap divisions: name, division, USBC ID, provided average, status. It shows Unverified by default; a filter switches to All (D-295).
2. Presses **Verify** on a row (one click, no note), or **Adjust**, which asks for the new average and a note.
3. Sees the row leave the Unverified list. Results, scores, lanes, and TV refetch and the marker goes (AVG-19).
4. Can adjust again, or remove the check, from the same row. **Details** shows the provided average, the verified average, the note, who, and when.

## Fields

| Field             | Type                 | Required  | Notes                                                            |
| ----------------- | -------------------- | --------- | ---------------------------------------------------------------- |
| `action`          | `verify` or `adjust` | Yes       |                                                                  |
| `average`         | integer              | On adjust | Whole, 1 to 300                                                  |
| `note`            | string               | On adjust | At most 500 characters. Why, or where the number came from       |
| `confirmWarnings` | boolean              | No        | The director confirmed the warnings of an earlier answer (D-201) |

## API

All web only (D-09). The vendor routes stay as they were except `VC-08` (AVG-16).

| Route                                                                      | Access               | Does                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/tournaments/{id}/averages`                                        | `registrations.read` | Rows for handicap-division registrations: `registrationId`, `bowlerName`, `divisionName`, `usbcId`, `providedAverage`, `status`, `averageInUse`, `note`, `verifiedBy`, `verifiedAt`, and `tournamentComplete`. `404` for an unknown tournament.                                                   |
| `PUT /v1/tournaments/{id}/registrations/{registrationId}/average-check`    | `averages.verify`    | Body per Fields. `200` with the new row. `400 { message, errors }` for a bad number, a missing note, a limit breach (field `average`), or a null average on verify. `404`. `409 { message, warnings }` when scores exist and `confirmWarnings` is missing. `409` when the tournament is complete. |
| `DELETE /v1/tournaments/{id}/registrations/{registrationId}/average-check` | `averages.verify`    | Removes the row. Same `409` rules.                                                                                                                                                                                                                                                                |

Changed existing routes: the lane page, check-in, results, scores, score entry, and TV reads (AVG-09, AVG-12, AVG-13); the registrations list (`average`, `averageStatus`); recap sheets (`withoutVerifiedAverage`); squad and sweeper complete and complete-info (AVG-18); desk and vendor create, append, edit, and `PATCH` (AVG-08, AVG-16).

## Data

`api/prisma/average-tables.sql` creates the table. Run it once per database before deploying, like the payout tables (`npm run db:tables` makes it locally). See [deployment.md](../deployment.md).

## Screens

- **Averages page:** table of registrations, reflowed into stacked rows on a phone. Verify, Adjust, and Details buttons. Verify and Adjust hide without `averages.verify`. The adjust form shows errors beside the field and links them with `aria-describedby`.
- **Marker:** an outline chip with text only, "Avg not verified" beside a name, "Not verified" in a table of averages.
- **Registrations, lane page, check-in sheet, results, scores, score entry, TV, recap dialog, complete dialog:** as in the rules above.
- Axe passes on the Averages page, the adjust form with errors, and Details. Nothing scrolls sideways at 320 px.

## Not built

- Bulk verify (D-295). The owner chose one bowler at a time.
- A history of past adjustments. A row holds the latest; the log holds the rest (D-292).
- A number on the TV or scores feeds. They carry only the yes or no flag.
- A verified badge on recap sheets. They print the handicap from the average in use.
- Any change to what the vendor's reads return. The registration site still sees the provided average.
