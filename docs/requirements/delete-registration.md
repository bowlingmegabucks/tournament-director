# Delete registration (desk)

Built on branch `deleteRegistration`. Migration source: [docs/migration/registrations.md](../migration/registrations.md) and [payments.md](../migration/payments.md).

The desk removes a whole registration: its squad and sweeper entries (with their lane positions), its payment records, and the registration itself. The bowler record stays. It is web only (D-209): the registration site keeps `DELETE /v1/registrations/{id}` ([registration-api.md](registration-api.md), `API-08`) with no warning step, and the vendor contract does not change (D-09).

Needs `registrations.write` (director and admin). The API key and a score keeper get `403`. A complete tournament refuses it (D-130).

## What the desk does

1. **Open it** from the red **Delete** button on a row of the Registrations page (its own last column, below a divider on a phone card), or from the **Danger zone** at the bottom of the edit page (D-214, D-215). Both open the same dialog. Neither shows without `registrations.write` or on a complete tournament.
2. **The dialog** reads the facts when it opens. It asks the legacy question, "Are you sure you want to delete this bowler's entire registration?", and lists each entry with its fee and a total under "Refund may be due, handled outside the app" (D-212). Cancel has focus first.
3. **A real payment** (a code not starting `Manual_`, amount above $0) adds "Paid outside this system: $85.00 (BowlingSite, 1 payment)" and a tick, "I know this bowler paid outside this system and any refund is handled outside the app." Delete stays off until the desk ticks (D-210, D-213).
4. **A refusal** (scores, or a complete tournament) shows the reasons and only Close (D-211).
5. **After a delete** the page goes to the Registrations list with a toast, "Maria Chen: Registration deleted." (D-213).

## API

All web only (D-09). Access `{ permission: 'registrations.write' }`, mounted on `/v1/tournaments/:id/registrations` beside the edit routes.

| Route                                                                 | Response                                                                                                                                                                                                                  | Errors                                                                                                                                                                                                       |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /v1/tournaments/{id}/registrations/{registrationId}/delete-info` | `200 { deleteInfo: { bowlerName, divisionName, tournamentComplete, hasScores, entries: [{ id, kind, date, entryFee }], entriesTotal, payments: [{ system, amount }], paidTotal } }`. `payments` holds real payments only. | `400` bad id; `401`; `403`; `404` tournament or registration                                                                                                                                                 |
| `DELETE /v1/tournaments/{id}/registrations/{registrationId}`          | `204`, no body                                                                                                                                                                                                            | `409 { message, errors: { tournament?, scores? } }` refusal; `409 { message, warnings, paid }` real payment not yet confirmed; `400` bad id, or `confirmWarnings` without `paid`; `404`; `401`; `403`; `503` |

## Screens

- **Registrations page:** a red outline Delete button in its own last column (no visible heading; a hidden "Delete" heading for screen readers), below a divider on a phone card.
- **Edit registration:** a "Danger zone" section below the form, outside it.
- **Delete dialog states:** loading, plain, real payment (warning, tick), refused, read error with Try again, deleting, and a failed delete with the reason. A server refusal after the dialog opened closes it and keeps an error toast until dismissed.
- Axe passes in dark and light mode on the list, each dialog state, and the Danger zone. Nothing scrolls sideways at 320 px.

## Not built

- Recording a refund or payment amount, a refund status, or a balance (Q-38, D-163, `PAY-05`).
- A delete in the lane page dialog (D-214).
- Any change to the vendor `DELETE /v1/registrations/{id}` or its `400` body (D-09).
