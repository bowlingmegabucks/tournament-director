# Divisions

Built on branches `tournamentDivisionsList` (list), `createDivision` (add, the first part of 0.6.0), `editDivision` (edit, the second part), and `deleteDivision` (delete, the third part). Migration source: [docs/migration/divisions.md](../migration/divisions.md).

The API reads, adds, edits, and deletes rows in the legacy `Divisions` table in the MariaDB database through Prisma (D-30). Reading is public (0.2.0). Adding, editing, and deleting need sign-in and `divisions.write` (director and admin, D-138, D-150, D-151).

## Fields

What `GET /v1/tournaments/{id}/divisions` returns for a division.

| Field                              | Type             | Required | Notes                                        |
| ---------------------------------- | ---------------- | -------- | -------------------------------------------- |
| `id`                               | UUID             | yes      |                                              |
| `number`                           | integer          | yes      | Display order. Not unique in old data (D-38) |
| `name`                             | text             | yes      | Not empty                                    |
| `gender`                           | `Male`, `Female` | no       | `null` means any. Stored as 0, 1, or NULL    |
| `minimumAge`, `maximumAge`         | integer          | no       | Age on the tournament start date             |
| `minimumAverage`, `maximumAverage` | integer          | no       |                                              |
| `handicapPercentage`               | integer          | no       | A whole percent: stored `0.90` is `90`       |
| `handicapBase`                     | integer          | no       | The score handicap counts up to              |
| `maximumHandicapPerGame`           | integer          | no       | Cap on handicap per game                     |

The vendor detail route (`API-04`) carries only `id, name, minimumAge, maximumAge, minimumAverage, maximumAverage, gender` per division (D-37, D-09).

A stored row is read when it has a UUID `id`, a non-empty `name`, a whole `number`, whole-number limits or NULL, and a gender of 0, 1, or NULL. Any other row is skipped and logged with its id (D-39). `DIV-01` to `DIV-11` do not run on read, so a stored number of 0 or an odd age range still shows.

## Add fields

What `POST /v1/tournaments/{id}/divisions` takes, with its limits (D-141). Limits are refused, never rounded. A box left blank, `""`, `null`, or a missing key all mean not set. The request has no `number`: the server picks it and drops one that is sent (D-139).

| Field                              | Type                         | Required | Notes                                                              |
| ---------------------------------- | ---------------------------- | -------- | ------------------------------------------------------------------ |
| `name`                             | text, trimmed, 1 to 100      | yes      | Unique in the tournament, ignoring case and outer spaces (D-140)   |
| `gender`                           | `Male`, `Female`, or not set | no       | Not set means any gender                                           |
| `minimumAge`, `maximumAge`         | whole number, 1 to 120       | no       | Minimum at most maximum (`DIV-05`)                                 |
| `minimumAverage`, `maximumAverage` | whole number, 1 to 300       | no       | Minimum at most maximum (`DIV-07`). Legacy stops at 299            |
| `handicapPercentage`               | whole number, 1 to 999       | no       | The percent as typed (90). Stored `0.90`. Over 100 asks to confirm |
| `handicapBase`                     | whole number, 0 to 300       | no       | Set with the percentage or not at all (`DIV-09`)                   |
| `maximumHandicapPerGame`           | whole number, 1 to 300       | no       | Only with a base and a percentage (`DIV-11`)                       |
| `confirmWarnings`                  | `true`                       | no       | Agrees to the warnings (D-142)                                     |

## Edit fields

What `PATCH /v1/tournaments/{id}/divisions/{divisionId}` takes: any of the add fields except `number`, plus `confirmWarnings`. A key left out stays as stored. A key sent as `""` or `null` clears the value (the name cannot be cleared). A key sent with the stored value is no change. An unknown key, `number` included, is `400` (D-146).

### Editing a field (D-147, D-148, D-149)

What decides whether a field may change. A warning appears only when the value really changes. "Registered" means bowlers registered in this division. "Scores" means any saved score, squad or sweeper, of a bowler registered in this division (`SCR-10`, D-148).

| Field                                                          | Free                                 | Asks the director to confirm                                                                                       | Refused                                      |
| -------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| `name`                                                         | Always, if no other division uses it |                                                                                                                    | Another division's name; complete tournament |
| `gender`, ages, averages                                       | Nobody registered                    | Bowlers registered (not retroactive; review them by hand, D-12)                                                    | Complete tournament                          |
| `handicapPercentage`, `handicapBase`, `maximumHandicapPerGame` | No scores                            | Scores exist (posted results change at once); a percent over 100 (D-142)                                           | Complete tournament                          |
| `handicapPercentage` set or cleared                            | Nobody registered                    | Bowlers registered (a handicap division needs a USBC ID, `REG-05`); joined with any other reason on the same field | Complete tournament                          |
| `number`                                                       |                                      |                                                                                                                    | Not editable (D-146)                         |

The pair rules (`DIV-05`, `DIV-07`, `DIV-09`, `DIV-11`) run on the merged values (the stored value for a box not sent), and only when a box of the pair is sent, so a stored odd pair never blocks a name fix. A pair failure is `400`; a refusal or a warning is `409` and saves nothing.

## Screens

- **Divisions** (`/tournaments/{id}/divisions`): a table, reached from the "Divisions" link in the tournament sidebar, which is marked as the current page there. Loading, error with Try again, and empty states. On narrow screens each row becomes a card. A "New division" link sits beside the heading for a user with `divisions.write`, hidden on a complete tournament (D-143). An "Edit" link per row (its own cell, "Edit {name}") sits in a column for a user with `divisions.write`, hidden on a complete tournament (D-149). A "Division created", "Division saved", or "Division deleted" toast shows after an add, an edit, or a delete and closes itself (D-144, D-154). An "Edit" link and a "Delete" button share the actions cell (see `DIV-12` delete screen).
- **New division** (`/tournaments/{id}/divisions/new`): the add form inside the tournament layout. The number is plain text ("one more than the highest"). Fields: name, gender (Any gender, Male, Female), Age limits, Average limits, and a Handicap group (percent with a "%" after the box, base, maximum per game). A visible label and hint on every box. Checks run on leaving a box and on save; a failed save shows a summary and moves focus to the first problem; Add shows "Saving…" and is disabled while it runs. A server field error shows under its box; a percent over 100 opens the confirm dialog; a complete tournament shows "This tournament is complete" in place of the form; any other failure is an error toast that stays until dismissed. A user without the permission sees the standard "No access" page; a signed-out visitor goes to sign in.

- **Edit division** (`/tournaments/{id}/divisions/{divisionId}/edit`): the add form filled with the stored values, inside the tournament layout. The number is plain text with "The number cannot change." Each box that asks for a confirmation says so before the director types ("Asks you to confirm: 12 bowlers are registered in this division. The change is not retroactive; review them by hand."), from `edit-info`. Only a box the director changed is checked and sent. A failed save shows a summary and moves focus to the first problem; a server field error (a used name) shows under its box; a warning opens the "Save these changes?" dialog; a complete tournament shows "This tournament is complete" in place of the form; an unknown division shows "Division not found"; any other failure is an error toast that stays until dismissed. The page reads the settings, the list, and the edit-info fresh on every open. A user without the permission sees the standard "No access" page; a signed-out visitor goes to sign in.
