# Lane assignments

Built on branches `laneAssignment-view` (slice one) and `migrate-lane-assignment-save` (slice two). Migration source: [docs/migration/lane-assignments.md](../migration/lane-assignments.md).

Slice one (D-55) built the squad and sweeper page, the lane page, and drag and drop. Slice two saves the move and keeps every open lane page fresh over server-sent events (D-216 to D-222). The page and its routes need sign-in since the lock-down (D-59, D-105): reading needs `lanes.read`; moving a bowler needs `lanes.assign`, held by the director and admin only. The API reads and writes the legacy `SquadRegistration` table (the `LaneAssignment` position) with its registration, average, and bowler through Prisma (D-30).

## Fields

What `GET /v1/tournaments/{id}/squads/{sessionId}/lanes` (and the `/sweepers/` twin) returns.

| Field        | Type                                                                    | Notes                                                                                                                                                                                                          |
| ------------ | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session`    | `{ id, kind, date, complete, startingLane, numberOfLanes, maxPerPair }` | `kind` is `squad` or `sweeper`. `date` is the center's local time with no zone                                                                                                                                 |
| `pairs[]`    | list                                                                    | One per lane pair: `{ firstLane, lanes, capacity, bowlers }`. `capacity` is `maxPerPair`. Pairs run from `startingLane`, two lanes at a time (an odd count ends with a one-lane pair; a count of 0 gives none) |
| `unassigned` | list                                                                    | Bowlers with no position (NULL or empty), sorted by last name, first name, then registration id                                                                                                                |
| `other`      | list                                                                    | Bowlers whose stored position is not `<lane><letter>` or names a lane outside the session, sorted by the text (D-61)                                                                                           |
| `divisions`  | list                                                                    | `{ id, number, name, entries }`: bowlers entered per division, 0 where nobody is, in division order                                                                                                            |

A bowler is `{ registrationId, name, firstName, lastName, divisionId, divisionName, average, position, pins, superSweeper }`.

| Field                   | Type              | Notes                                                                                        |
| ----------------------- | ----------------- | -------------------------------------------------------------------------------------------- |
| `name`                  | text              | `First Last`, plus `, Suffix` (`BWL-13`)                                                     |
| `firstName`, `lastName` | text              | Not empty. For the sort                                                                      |
| `average`               | integer or `null` | The registration's average                                                                   |
| `position`              | text              | The stored position, such as `15A`. `''` when not assigned                                   |
| `pins`                  | integer           | The handicap per game on a squad (`SCR-07`); the bonus pins per game on a sweeper (`SCR-09`) |
| `superSweeper`          | boolean           | Always sent; the page shows Y or N for a sweeper only                                        |

Never sent (`BWL-17`): SSN, gender, date of birth, address, email, phone, payments. The query names columns.

A stored entry is read when it has a UUID registration id, a division id that is a UUID, a whole-number or empty average, and a bowler with a first and last name. Any other row is skipped and logged with its id, once per process (D-51). An entry whose division is not one of the tournament's is left out and logged the same way.

## API

| Route                                                 | Response                                                                                                         | Errors                                                                                                                                | Vendor-visible |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `GET /v1/tournaments/{id}/squads/{sessionId}/lanes`   | `200 { session, pairs: [{ firstLane, lanes, capacity, bowlers }], unassigned, other, divisions }` (Fields above) | `400` not a UUID; `404` unknown tournament or squad; `422` bowlers per pair not 2 to 5; `500` bad tournament row; `503` database down | No. Web only   |
| `GET /v1/tournaments/{id}/sweepers/{sessionId}/lanes` | Same, with `kind: "sweeper"` and bonus pins in `pins`                                                            | Same, `404` for a sweeper                                                                                                             | No. Web only   |
| `PUT /v1/tournaments/{id}/squads/{sessionId}/lanes/{registrationId}` and `/sweepers/` | `200 { position }` (`''` when unassigned) | `400` bad body or a lane that starts no pair; `404` unknown tournament, session, or a bowler not on it; `409` pair full, or session or tournament complete; `422` bowlers per pair not 2 to 5; `503` database down | No. Web only |
| `GET /v1/tournaments/{id}/squads/{sessionId}/events` and `/sweepers/` | `text/event-stream` of `changed` messages | `400` not a UUID; `404` unknown tournament or session; `503` past 500 streams | No. Web only |

The two reads and the stream need `lanes.read` since the lock-down (D-59, D-52, D-105, `API-22`): 401 with no sign-in, 403 for the API key or a user without the permission. The move needs `lanes.assign` (D-216). The API's `features/lanes/types.ts` and the web app's `features/lanes/types.ts` carry the same fields; change both together. The API builds the pairs, so the page does no grouping.

## Screens

- **Squad or sweeper page** (`/tournaments/{id}/squads/{squadId}`, `/sweepers/{sweeperId}`): the page header (breadcrumb, date and time, Open or Complete) and two tabs, "Lane assignments" and "Scores". The tournament sidebar does not change, and "Squads" (or "Sweepers") stays marked. Results and the Complete button come with their features (D-60). The "Lane assignments" tab shows only to users with `lanes.read`. The page root opens that tab for them and the Scores tab for everyone else, and a signed-out visit to `.../lanes` goes to `/login` (D-105).
- **Lane assignments** (`.../lanes`): the division strip, then the unassigned list (left) and the lane pairs (right), each scrolling on its own. On a screen wide enough for two columns the areas fill what is left of the window, so the page itself does not scroll (checked at window heights of 700 to 1080px); in a very short window, or when a line above wraps, the page scrolls a little. On a phone the areas stack. A "Move" or "Assign to lanes" button sits on every bowler of an open session, for a user who holds `lanes.assign`. A status line over the division strip says whether the page is live (`LAN-21`); an open session only. Page title: `Lane assignments · {date} · {tournament} · Tournament Director`.

## Notes

- **The seat the screen shows first is a guess.** `web/src/features/lanes/optimisticMove.ts` picks the seat and moves the bowler at once (D-220); the API picks the real one, and its answer replaces the guess. A refusal puts the page back as it was. The page also refetches after every save.
- **One instance.** The hub that tells open pages lives in the Node process (D-221). With two App Service instances a change on one never reaches a page on the other: Q-39. See [deployment.md](../deployment.md#live-updates-sse-d-217).
- **Pattern for the rest.** Scores and Results keep their 15 s poll for now (D-222) and move to the same stream, with an open route, in their own slice. [api-standards.md](../api-standards.md#live-updates-sse) holds the pattern.
- **Not built yet:** `LAN-12` copy is dropped (D-67); add to squad, new registration, and remove from squad are built (see [edit-registration.md](edit-registration.md)). Recap sheets and the cross are built: [recap-sheets.md](recap-sheets.md). `LAN-07` and `LAN-08` are not needed: the server picks the seat (D-57).
- **Mock mode.** The mock `PUT` keeps the move and tells the open mock stream, so `npm run dev:mocks` and the e2e tests save and refetch like the real API.
