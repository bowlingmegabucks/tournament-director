# Lane assignments

Built on branch `laneAssignment-view`. Migration source: [docs/migration/lane-assignments.md](../migration/lane-assignments.md).

This is slice one of two (D-55). It builds the squad and sweeper page, the lane page, drag and drop, and a way to move a bowler **on screen only**. **Nothing saves**: the move command waits for the lock-down release (D-52). The page and its route are **public for 0.2.0 only**: they show bowler names and averages, and the lock-down release puts them behind auth (D-59, tracked in [docs/v1-requirements.md](../v1-requirements.md)). The API reads the legacy `SquadRegistration` table (the `LaneAssignment` position) with its registration, average, and bowler through Prisma (D-30).

## Fields

What `GET /v1/tournaments/{id}/squads/{sessionId}/lanes` (and the `/sweepers/` twin) returns.

| Field        | Type | Notes                                                                                                                                     |
| ------------ | ---- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `session`    | `{ id, kind, date, complete, startingLane, numberOfLanes, maxPerPair }` | `kind` is `squad` or `sweeper`. `date` is the center's local time with no zone                         |
| `pairs[]`    | list | One per lane pair: `{ firstLane, lanes, capacity, bowlers }`. `capacity` is `maxPerPair`. Pairs run from `startingLane`, two lanes at a time (an odd count ends with a one-lane pair; a count of 0 gives none) |
| `unassigned` | list | Bowlers with no position (NULL or empty), sorted by last name, first name, then registration id                                           |
| `other`      | list | Bowlers whose stored position is not `<lane><letter>` or names a lane outside the session, sorted by the text (D-61)                       |
| `divisions`  | list | `{ id, number, name, entries }`: bowlers entered per division, 0 where nobody is, in division order                                      |

A bowler is `{ registrationId, name, firstName, lastName, divisionId, divisionName, average, position, pins, superSweeper }`.

| Field                         | Type              | Notes                                                                                                |
| ----------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------- |
| `name`                        | text              | `First Last`, plus `, Suffix` (`BWL-13`)                                                             |
| `firstName`, `lastName`       | text              | Not empty. For the sort                                                                              |
| `average`                     | integer or `null` | The registration's average                                                                           |
| `position`                    | text              | The stored position, such as `15A`. `''` when not assigned                                           |
| `pins`                        | integer           | The handicap per game on a squad (`SCR-07`); the bonus pins per game on a sweeper (`SCR-09`)         |
| `superSweeper`                | boolean           | Always sent; the page shows Y or N for a sweeper only                                                |

Never sent (`BWL-17`): SSN, gender, date of birth, address, email, phone, payments. The query names columns.

A stored entry is read when it has a UUID registration id, a division id that is a UUID, a whole-number or empty average, and a bowler with a first and last name. Any other row is skipped and logged with its id, once per process (D-51). An entry whose division is not one of the tournament's is left out and logged the same way.

## API

| Route                                                 | Response                                                                                                          | Errors                                                              | Vendor-visible |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------- |
| `GET /v1/tournaments/{id}/squads/{sessionId}/lanes`   | `200 { session, pairs: [{ firstLane, lanes, capacity, bowlers }], unassigned, other, divisions }` (Fields above) | `400` not a UUID; `404` unknown tournament or squad; `422` bowlers per pair not 2 to 5; `500` bad tournament row; `503` database down | No. Web only   |
| `GET /v1/tournaments/{id}/sweepers/{sessionId}/lanes` | Same, with `kind: "sweeper"` and bonus pins in `pins`                                                             | Same, `404` for a sweeper                                           | No. Web only   |

Public today (D-27); both get a signed-in label in the lock-down release (D-59, D-52). The API's `features/lanes/types.ts` and the web app's `features/lanes/types.ts` carry the same fields; change both together. The API builds the pairs, so the page does no grouping.

## Screens

- **Squad or sweeper page** (`/tournaments/{id}/squads/{squadId}`, `/sweepers/{sweeperId}`): the page header (breadcrumb, date and time, Open or Complete) and one tab, "Lane assignments". The tournament sidebar does not change, and "Squads" (or "Sweepers") stays marked. Scores, Results, and the Complete button come with their features (D-60).
- **Lane assignments** (`.../lanes`): the division strip, then the unassigned list (left) and the lane pairs (right), each scrolling on its own. On a screen wide enough for two columns the areas fill what is left of the window, so the page itself does not scroll (checked at window heights of 700 to 1080px); in a very short window, or when a line above wraps, the page scrolls a little. On a phone the areas stack. A "Move" or "Assign to lanes" button sits on every bowler of an open session. Page title: `Lane assignments · {date} · {tournament} · Tournament Director`.

## Notes

- **On-screen moves are temporary.** `web/src/features/lanes/tempMoves.ts` picks the seat and applies moves over the API's page during render. A refresh, or opening another session, drops them. Slice two replaces it with the move command, where the API picks the seat and returns the position, and `tempMoves.ts` is deleted.
- **Designed, not built** (D-57): the page will send the registration and the odd lane of the pair (or nothing, to unassign). The API picks the first free seat in fill order, answers 409 `{ message }` when the pair is full, refuses on a complete session (D-10), and returns the new position; the page updates its labels from it. This needs the lock-down release first (D-52).
- **Open:** live updates when several people work at once (Q-27) and what happens when two people race for the last seat of a pair (Q-28).
- **Not built yet:** `LAN-05`, `LAN-06`, `LAN-09` (the move), `LAN-12` (add to squad, new registration, remove from squad; copy is dropped, D-67). Recap sheets and the cross are built: [recap-sheets.md](recap-sheets.md). `LAN-07` and `LAN-08` are not needed: the server picks the seat (D-57).

## Local data

`npm run db:seed` gives each sample tournament lane positions. Squad 2 (open, lanes 1 to 24, four per pair) has three bowlers on the first pair and two waiting. Squad 1 (complete) has bowlers placed and one waiting. Sweeper 1 has one bowler on a lane and two waiting. Averages are seeded, and one bowler has none. Running the seed again resets these positions.
