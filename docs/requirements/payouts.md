# Payouts

Built on branch `payout`. New in the 1.0.0 work: legacy has no prize amounts and no payout report ([proposed-features.md](../migration/proposed-features.md), Q-22), so the rules are new (`PAY-01` to `PAY-21`). Decisions: D-267 to D-285 in [decisions-and-questions.md](../migration/decisions-and-questions.md). This release stores the data only; the 1099 report, SSN use, a dollar limit, and year totals come later (D-282).

## What a payout is

One row says what one event paid one bowler. The events are a squad, a sweeper, the super sweeper, and the finals of one division. Each row holds only what that event paid, never another event's cash, so a later report adds rows to get a bowler's total (D-267). The finals are a one-game shootout of the division winners across divisions, so a finals payout carries an amount and an optional note and no place (D-277).

## Fields

`Payouts` table, from [api/prisma/payout-tables.sql](../../api/prisma/payout-tables.sql) (run once per database, no foreign keys, D-281):

| Field                      | Type            | Notes                                                                                                            |
| -------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------- |
| `Id`                       | uuid            |                                                                                                                  |
| `TournamentId`             | uuid            | `Registrations` has no tournament column (Q-26), so it is kept here                                              |
| `Source`                   | text            | `squad`, `sweeper`, `superSweeper`, `finals`                                                                     |
| `EventId`                  | uuid            | The squad or sweeper id; the division id for finals; the tournament id for the super sweeper                     |
| `RegistrationId`           | uuid            | The payee. Unique with `Source` and `EventId`: a payee has at most one payout per event                          |
| `Amount`                   | `DECIMAL(7,2)`  | Above $0 and at most $99,999.99 (`PAY-07`). Money crosses the wire as text, `"100.00"`; the code holds cents      |
| `Note`                     | text, 200 max   | Required for a bowler the results did not infer (`PAY-06`)                                                       |
| `Paid`                     | boolean         | `PAY-13`                                                                                                         |
| `CreatedAt`, `CreatedBy`   | time, user id   |                                                                                                                  |
| `UpdatedAt`, `UpdatedBy`   | time, user id   | The last editor only; the log line holds the counts                                                              |

## API

All web only (D-09, D-96), under `/v1/tournaments/{id}/payouts`. The API key cannot reach them.

| Route                                                                          | Access           | Does                                                                                                                            |
| ------------------------------------------------------------------------------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `GET /`                                                                        | `payouts.read`   | `{ payouts, summary, tournamentComplete }`                                                                                      |
| `GET /totals?min=`                                                             | `payouts.read`   | `{ bowlers: [{ registrationId, name, divisionName, count, total, unpaidTotal }] }`                                              |
| `GET /squad/{sessionId}`, `/sweeper/{sessionId}`, `/super-sweeper`, `/finals/{divisionId}` | `payouts.read`   | `{ sheet }`: `event`, `status` (`open`, `notReady`, `locked`), `reason`, `payees` (inferred, plus bowlers added by hand), `others`, `tournamentComplete` |
| `PUT` on the same four paths                                                   | `payouts.write`  | Body `{ payouts: [{ registrationId, amount, note, paid }], confirmPaid? }` (at most 500 rows). `200 { sheet }`; `400` with `errors` keyed `amount:<id>` and `note:<id>`; `409` with `errors.event`, or with `warnings` and `paidChanges` |
| `PATCH /{payoutId}`                                                            | `payouts.write`  | `{ paid }` → `200 { payout }`; `409` when the tournament is complete                                                            |

`404` for an unknown tournament, event, or payout; `400` for an id that is not a UUID. The existing `GET /v1/tournaments/{id}/complete-info` adds the three payout counts (`PAY-15`).

## Screens

- **A squad or sweeper:** a Payouts tab (needs `payouts.read`) with the disclaimer, the figures, an Enter payouts button (needs `payouts.write`, off with the reason until the session is complete), and the saved payouts as a table that reflows to cards on a phone.
- **Super sweeper:** a "Super sweeper payouts" link on the Sweepers page. **Finals:** a "Pay finals" link (read-only users see "Finals payouts") beside the division chooser on the Seeding page, opening `/tournaments/{id}/seeding/{divisionId}/payouts`.
- **The entry sheet:** a dialog from 40 rem and a full-screen sheet on a phone. Inferred bowlers first, each with an amount box, a note, and a Paid tick; Same amount for all; Add another bowler (search); the running total; one Save. A mistake shows next to its row; a paid payout that would change asks first. Cancel asks first when something was typed.
- **The full list** (sidebar Payouts, `/tournaments/{id}/payouts`): By payout and By bowler.
- **Results pages and the TV:** "Payout $100.00" under a casher's name (and a finalist's on Seeding), in the tables, the phone cards, the TV rows, and the printed pages.
