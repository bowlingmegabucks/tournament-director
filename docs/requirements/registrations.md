# Registrations (list)

Built on branch `registration-list`. Migration source: [docs/migration/registrations.md](../migration/registrations.md) and [docs/migration/bowlers.md](../migration/bowlers.md).

This slice is read-only and **public for 0.2.0 only**. It shows bowler names, USBC IDs, and which sessions each bowler entered, which the public does not need to see. The release right after 0.3.0 puts this route and page behind auth (D-46, D-52; tracked in [docs/v1-requirements.md](../v1-requirements.md)). The API reads the legacy `Registrations`, `SquadRegistration`, and `Bowlers` tables through Prisma (D-30). The `Bowler` model exists only to support this list: it has no SSN column, and there is no bowler route (D-47). Create, change, delete, and every other bowler field wait for sign-in (0.3.0) and commands (0.4.0 and up).

## Fields

What `GET /v1/tournaments/{id}/registrations` returns for a registration.

| Field                                 | Type         | Notes                                                                                                                   |
| ------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `id`                                  | UUID         |                                                                                                                         |
| `bowler.id`                           | UUID         |                                                                                                                         |
| `bowler.name`                         | text         | `First Last`, plus `, Suffix` when there is one (`BWL-13`)                                                              |
| `bowler.firstName`, `bowler.lastName` | text         | Not empty. For the filter                                                                                               |
| `bowler.usbcId`                       | text         | `""` when the bowler has none. The page shows a dash                                                                    |
| `divisionId`, `divisionName`          | UUID, text   | The tournament comes from the division                                                                                  |
| `squadIds`, `sweeperIds`              | list of UUID | The qualifying squads and sweepers the bowler entered. The page shows their counts and lists them in a popup (`REG-28`) |
| `superSweeper`                        | boolean      | Shown as a check mark, or blank                                                                                         |

And the `summary`, for the whole tournament (`REG-24`, D-50).

| Field                            | Type    | Notes                                                                                                                       |
| -------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------- |
| `registrations`, `superSweepers` | integer | Bowlers registered; how many opted into the super sweeper                                                                   |
| `divisions[]`                    | list    | `{ id, number, name, entries }`. `entries` is the squads its bowlers entered; sweepers do not count                         |
| `squads[]`, `sweepers[]`         | list    | `{ id, date, complete, entries }`. A complete squad counts (D-06). One nobody entered lists `0`. `complete` feeds the popup |

Never sent (`BWL-17`): SSN, gender, date of birth, address, email, phone, average, payments, lane positions.

A stored registration is read when it has a UUID `id` and a bowler with a non-empty first and last name. Any other row is skipped and logged with its id, once per process (D-51). A `SquadRegistration` row for a squad of another tournament, or for a session whose `SquadType` is neither 0 nor 1, is ignored. `BWL-01` to `BWL-12` run on save, not on read.

## API

| Route                                    | Response                                                                                                                                                                                                                                                                                                                          | Errors                                                                                    | Vendor-visible |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------- |
| `GET /v1/tournaments/{id}/registrations` | `200 { registrations: [{ id, bowler: { id, name, firstName, lastName, usbcId }, divisionId, divisionName, squadIds, sweeperIds, superSweeper }], summary: { registrations, superSweepers, divisions: [{ id, number, name, entries }], squads: [{ id, date, complete, entries }], sweepers: [{ id, date, complete, entries }] } }` | `400` not a UUID; `404` unknown tournament; `500` bad tournament row; `503` database down | No. Web only   |

Public today (D-27); it gets a signed-in label in the lock-down release (D-46, D-52). The API's `types.ts` and the web app's `types.ts` carry the same fields; change both together. The tournament comes from the division, since `Registrations` has no `TournamentId` column (Q-26).

## Screens

- **Registrations** (`/tournaments/{id}/registrations`): reached from the "Registrations" link in the tournament sidebar, which marks the current page. A summary, a search box ("Filter by name or USBC ID", with a hint), and a table. A squad or sweeper count above 0 opens a popup listing them (`REG-28`). A squad or sweeper count above 0 opens a popup listing them (`REG-28`). A blank super sweeper shows nothing; screen readers hear "Yes" or "No". On a narrow screen each row becomes a card, and a blank super sweeper is left out of it. Loading (the shared `Loading` component: dots, words, placeholder rows, D-53), error with Try again, empty, and no-match states. No add, edit, or delete button until sign-in exists (D-21).

## Local data

`npm run db:seed` adds seven bowlers and registrations to each of the four sample tournaments: two bowlers named Joe Fontaine, one with no USBC ID, one with a suffix, two super sweeper entries, a complete squad with entries, and a squad nobody entered. Running it twice adds nothing. The seed never writes an SSN.
