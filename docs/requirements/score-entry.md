# Score entry

Built on branch `scores`. Migration source: [docs/migration/scores.md](../migration/scores.md#entry-and-validation). The read side is in [scores.md](scores.md).

The score keeper types each bowler's game score into the new app, one score at a time, on a phone or a tablet, and every open Scores tab shows it at once. Entry needs sign-in and `scores.write` (the score keeper, director, and admin hold it). The public Scores tab stays public and now updates over a stream instead of polling (D-232). Copying scores in from a spreadsheet (`RPT-07`) is dropped (D-67).

## How entry works

Bowlers change pairs after each game, so a pair of lanes in game 2 holds bowlers who started elsewhere. Entry therefore starts from the **game**: the board picks a game and lists the pairs of lanes as they are bowled in that game; a pair's sheet takes one score for each bowler on it (D-230). The lane of each bowler for each game is the cross (`LAN-18`, `LAN-19`) worked out in the API from the saved start lane and the **skip** stored for the session (D-234, D-235). Lanes that break down mid-squad are out of scope: the keeper uses Find a bowler (D-236).

## Fields

What `GET /v1/tournaments/{id}/squads/{sessionId}/scores/games` (and the `/sweepers/` twin) returns.

| Field         | Type                                  | Notes                                                                                           |
| ------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `session`     | `{ id, kind, date, complete, games }` | `games` is the session's game count: a squad's is the tournament's, a sweeper's its own         |
| `skip`        | `staggered` or `same`                 | The stored skip (D-235). No row means `staggered`                                               |
| `games[]`     | list                                  | Exactly one per game 1 to `games`. A stored game above the count is ignored here (D-238)        |
| `withoutLane` | integer                               | Bowlers with no lane or a position outside the lanes. Not listed, cannot be entered here (D-71) |

A game is `{ game, entered, total, pairs }`: `entered` bowlers have a score in it, `total` bowlers have a lane. A pair is `{ firstLane, lanes, bowlers }`, in lane order. A bowler is `{ registrationId, name, divisionName, lane, score, scores, total }`: `lane` is the label for that game (`13A`), `score` is that game's score or `null`, `scores` holds every game, `total` is the scratch sum (D-68). A stored 0 stays 0: it is a missed game (D-229).

Never sent (`BWL-17`): SSN, gender, date of birth, address, email, phone, average, payments.

## API

| Route                                                   | Access                     | Response                            | Errors                                                                                                                                                        | Vendor-visible |
| ------------------------------------------------------- | -------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| `GET …/scores/games`                                    | `scores.write`             | `200` the games view (Fields above) | `400` not a UUID; `404` tournament or session; `422` pairs setting; `500` bad row; `503` database                                                             | No. Web only   |
| `PUT …/scores/{registrationId}/{game}` body `{ score }` | `scores.write`, no API key | `200 { scores, total }`             | `400` score or game out of range, or a body that is not `{ score: number }`; `404` tournament, session, or bowler not entered; `409` complete; `503` database | No. Web only   |
| `DELETE …/scores/{registrationId}/{game}`               | `scores.write`, no API key | `200 { scores, total }`             | As `PUT`, plus `404` no score to clear and `409` "Clear game N first." when a later game holds a score                                                        | No. Web only   |
| `GET …/scores/events`                                   | public                     | `text/event-stream`                 | `404` unknown session; `503` too many streams                                                                                                                 | No. Web only   |
| `GET …/skip`                                            | `lanes.read`               | `200 { skip }`                      | `404`; `503`                                                                                                                                                  | No. Web only   |
| `PUT …/skip` body `{ skip }`                            | `scores.write`, no API key | `200 { skip }`                      | `400` not `staggered` or `same`; `404`; `409` complete session or tournament                                                                                  | No. Web only   |

Every route also exists under `/sweepers/{sessionId}/…`. The recap route (`GET …/recap-sheets`) now also answers the stored `skip`.

- **Rate limit (D-232).** Everything under `…/scores` and `…/skip`, saves and the stream included, counts in its own bucket, `LIVE_RATE_LIMIT_MAX` (default 600 a minute per address), so many phones on one venue address do not use up the 100 of every other route.
- **Cache.** The public Scores page keeps its answer for 5 s (`LIVE_CACHE_MS`). A save drops that session's cached answer before it publishes, so the refetch it causes is never stale.
- **Writes.** One serializable transaction with retry reads the tournament, session, entry, and the bowler's scores, runs the pure plan (`scorePlan.ts`), and writes only the games it names, so two keepers saving one bowler together cannot both fill the same gap.
- **Logs.** Ids, the game, and the count of filled games; never a name.
- **Database.** One table we add, `SessionSkip`, from `api/prisma/score-tables.sql` (run once on each database before the release that ships it; see [deployment.md](../deployment.md)). `SquadScores` has no change.

## Screens

- **Enter scores** link on the Scores tab (needs `scores.write`; hidden on a complete session or tournament): opens `/tournaments/{id}/squads/{sessionId}/scores/entry` (or `/sweepers/…`). A signed-out visitor sent to the address goes to `/login`.
- **Game board** (`…/scores/entry/{game}`): the live line, a game switch with "n of m", the skip (two radios, saved at once, off on a complete session), Find a bowler, the From and To lane boxes with Show all, and one tile for each pair with a words-and-symbol badge. States: loading, error with Try again, setup problem, no lanes yet, nothing in the range, complete. `…/scores/entry` goes to the first game that misses a score.
- **Pair sheet** (`…/scores/entry/{game}/{firstLane}`): previous and next pair links, one block for each bowler, an "all scores are in" line when they are. A box saves on Next, Enter, or leaving it (never twice), keeps what the keeper typed until its save succeeds (a live update never replaces typing), and uses `inputmode="numeric"` so a phone shows the number pad only. There is no `maxlength`: the box keeps three digits itself, so a paste of "1x2y3456" still gives "123".
- **Tablet and desktop:** from 48 rem the board is the left pane (sticky, only its list of pairs scrolls) and the sheet is the right. Below it one shows at a time.
- **Recap dialog:** the skip radios start from the stored skip and save when changed; without `scores.write` they are off.

## Notes

- **Not built:** results on the stream (built: `RES-44`, D-241); reopening a complete session or editing a score after Complete (D-10); handicap, bonus pins, and rank on the entry screens (D-68); a per-game lane override when a lane breaks (D-236); a check that a score looks too low or high; offline queueing.
- **Decisions:** D-228 (one score at a time), D-229 (fill gaps with 0), D-230 (game board and sheet), D-231 (complete is locked on the server), D-232 (public stream, cache drop, own rate limit), D-233 (results next), D-234 (games route), D-235 (stored skip), D-236 (breakdown out of scope), D-237 (blank cells, names in the status line), D-238 (game above the count refused).
- **Mocks.** The mock server (`npm run dev:mocks`, e2e) keeps saves in memory and tells its streams; its lane labels are made up (`mocks/gamesData.ts`). Only the API works out the real cross.
- **Mutation.** `scorePlan.ts`, `gamesView.ts`, and `scoreRoutes.ts` are tested with Stryker; the in-memory and Prisma writers are excluded as the other writers are.
