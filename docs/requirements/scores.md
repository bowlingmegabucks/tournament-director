# Scores (view)

Built on branch `scores-view`. Migration source: [docs/migration/scores.md](../migration/scores.md).

This is the read-only slice: the Scores tab of a squad or sweeper shows each bowler's saved game scores, grouped by lane pair. **Entry, ranking, and live push come later.** Scores are scratch pins only; handicap and bonus pins wait for results (D-68). The route and tab are **public for good** (D-70): viewers who are not signed in watch scores come in. Only entry will need sign-in. The API reads the legacy `SquadScores` table through Prisma (D-30), read only.

## Fields

What `GET /v1/tournaments/{id}/squads/{sessionId}/scores` (and the `/sweepers/` twin) returns.

| Field     | Type                                  | Notes                                                                                                                                                                                         |
| --------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session` | `{ id, kind, date, complete, games }` | `kind` is `squad` or `sweeper`. `date` is the center's local time with no zone. `games` is the number of columns: the session's game count, or the highest stored game if that is more (D-69) |
| `pairs[]` | list                                  | One per lane pair that holds a bowler: `{ firstLane, lanes, bowlers }`. A pair with no bowler is left out (D-73). Order and bowler order as the lane page (`LAN-04`)                          |
| `noLane`  | integer                               | Bowlers with no position. They are counted, not listed (D-71)                                                                                                                                 |
| `other`   | list                                  | Bowlers whose stored position fits no pair of this session, sorted by the text (D-61, D-71)                                                                                                   |

A bowler is `{ registrationId, name, divisionName, position, scores, total }`.

| Field    | Type                      | Notes                                                                                                   |
| -------- | ------------------------- | ------------------------------------------------------------------------------------------------------- |
| `name`   | text                      | `First Last`, plus `, Suffix` (`BWL-13`)                                                                |
| `scores` | list of integer or `null` | One entry per column. `null` is a game with no score; a stored 0 stays 0 (D-69)                         |
| `total`  | integer                   | The scratch sum of the scores present, 0 when there are none (D-68). Not a result: no handicap, no rank |

Never sent (`BWL-17`): SSN, gender, date of birth, address, email, phone, average, payments. The query names columns.

## API

| Route                                                  | Response                                               | Errors                                                                                             | Vendor-visible |
| ------------------------------------------------------ | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- | -------------- |
| `GET /v1/tournaments/{id}/squads/{sessionId}/scores`   | `200 { session, pairs, noLane, other }` (Fields above) | `400` not a UUID; `404` unknown tournament or squad; `500` bad tournament row; `503` database down | No. Web only   |
| `GET /v1/tournaments/{id}/sweepers/{sessionId}/scores` | Same, with `kind: "sweeper"`                           | Same, `404` for a sweeper                                                                          | No. Web only   |

Public for good (D-70, D-27). The API's `features/scores/types.ts` and the web app's `features/scores/types.ts` carry the same fields; change both together. The API builds the pairs by reusing `loadLanePage` (`checkSeats: false`), so the page does no grouping.

## Screens

- **Scores tab** (`/tournaments/{id}/squads/{squadId}/scores`, `/sweepers/{sweeperId}/scores`): under the page header from [lane-assignments.md](lane-assignments.md) (`LAN-15`). Above the tables, the complete line and the no-lane note when they apply. Then one table per lane pair, then "Other positions" when there are any.

## Notes

- **Not built yet:** score entry and edit (`SCR-01` to `SCR-06`, `SCR-15`), the server refusal on a complete session (`SCR-14`, D-10), ranking and handicap (`SCR-07` to `SCR-09`, `SCR-11`, `SCR-12`, with results), and Complete with its no-show zeros (`SQD-15`). The view already shows stored zeros.
- **Open:** how live updates reach every open screen, signed in or not. SSE for everyone plus a separate way to send scores is acceptable; a deeper analysis is due with score entry, and with lane assignment edits (Q-33, Q-27, Q-28).
- **Local data:** `npm run db:seed` adds 20 scores to each sample tournament: squad 1 (complete) with every game and one no-show, squad 2 (open) part scored on its first pair, sweeper 1 with two of three games for one bowler. Running the seed again resets them.
