# Squads and sweepers

Built on branches `squadSweeperList` (the lists), `createSquad` (add squad and add sweeper, the first two parts of 0.7.0), `editSquad` (edit squad and edit sweeper, the third part), `deleteSquad` (the fourth), and `completeSquad` (complete squad and complete sweeper, the fifth). Migration source: [docs/migration/squads-and-sweepers.md](../migration/squads-and-sweepers.md).

The lists are read-only and public (0.2.0); adding, editing, or deleting a squad or a sweeper needs sign-in and `squads.write` (director and admin, D-167, D-174, D-184). The API reads the legacy `Squads` table (squads and sweepers share it, told apart by `SquadType`) and the `SweeperDivision` table through Prisma (D-30). Deleting and completing need `squads.write` too (D-187, D-193).

## Fields

What `GET /v1/tournaments/{id}/squads` returns for a squad.

| Field                                                                | Type    | Notes                                                                                                  |
| -------------------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------ |
| `id`                                                                 | UUID    |                                                                                                        |
| `date`                                                               | text    | The center's local time with no zone: `2026-10-24T09:00:00`                                            |
| `complete`                                                           | boolean | Shown as Open or Complete                                                                              |
| `startingLane`, `numberOfLanes`, `maxPerPair`                        | integer | A stored 0 for `numberOfLanes` shows as "Not set"; a first lane of 0 shows just the count ("12 lanes") |
| `entryFee`, `finalsRatio`, `cashRatio`                               | number  | The squad's own value if set, else the tournament's (`TRN-12`)                                         |
| `entryFeeOverridden`, `finalsRatioOverridden`, `cashRatioOverridden` | boolean | True when the squad sets its own value. The card adds "(override)"                                     |

What `GET /v1/tournaments/{id}/sweepers` returns for a sweeper.

| Field                                         | Type     | Notes                                                                                          |
| --------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------- |
| `id`, `date`, `complete`, lanes, `maxPerPair` | as above |                                                                                                |
| `entryFee`, `games`, `cashRatio`              | number   | The sweeper's own; never inherited (D-43)                                                      |
| `bonusPins`                                   | list     | `{ divisionId, divisionName, bonusPinsPerGame }`, only where pins are not 0, in division order |

The vendor detail route (`API-04`) carries only `id, date, entryFee` per squad (`entryFee` is `null` when the squad uses the tournament fee) and `id, date, entryFee, games` per sweeper (D-41, D-09).

A stored row is read when it has a UUID `id` and a valid date; a sweeper also needs a fee, games, and a cash ratio. Any other row is skipped and logged with its id (D-42). The vendor arrays on the tournament detail come from the same read, so a skipped row is missing there too. A row whose `SquadType` is not 0 (squad) or 1 (sweeper) is never read. `SQD-01` to `SQD-12` run on save, not on read, so an odd lane count or a date outside the tournament still shows.

## Add squad fields

What `POST /v1/tournaments/{id}/squads` takes, with its limits (D-168 to D-170). Limits are refused, never rounded (D-125). A fee or ratio left blank, `""`, `null`, or a missing key means the tournament's value and is stored as NULL. The request is strict: an unknown key, `complete` included, is `400`.

| Field                      | Type                                 | Required | Notes                                                                                           |
| -------------------------- | ------------------------------------ | -------- | ----------------------------------------------------------------------------------------------- |
| `date`                     | `YYYY-MM-DDTHH:mm` (seconds only `00`) | yes      | The center's local time, a real day and time, within the tournament dates (`SQD-03`)            |
| `startingLane`             | whole number, odd, 1 to 199          | yes      | `SQD-06`, D-168                                                                                 |
| `numberOfLanes`            | whole number, even, 2 to 200; with the starting lane it must end at lane 200 or lower | yes      | `SQD-05`, D-168, D-179                                                                                 |
| `maxPerPair`               | whole number, 2 to 5                 | yes      | `SQD-04`. Matches the lane page (D-56, answers Q-10)                                            |
| `entryFee`                 | number, 0 to 999.99, two decimals    | no       | `SQD-08`. A typed 0 is set, not blank                                                           |
| `finalsRatio`, `cashRatio` | number, 1.1 to 99.9, one decimal     | no       | `SQD-02`                                                                                        |

## Add sweeper fields

What `POST /v1/tournaments/{id}/sweepers` takes (D-174 to D-177). The date, lanes, and max per pair follow the add squad table above (`SQD-10`). Limits are refused, never rounded (D-125). The request is strict: an unknown key, `complete` and `finalsRatio` included, is `400`. A sweeper's fee, games, and cash ratio are its own and always required.

| Field           | Type                                              | Required | Notes                                                                                                                                                       |
| --------------- | ------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `date`, `startingLane`, `numberOfLanes`, `maxPerPair` | as for a squad               | yes      | `SQD-10`. Messages say "Sweeper" (for example "Sweeper date must be after tournament start")                                                                |
| `entryFee`      | number, above 0, up to 999.99, two decimals       | yes      | `SQD-12`, D-175. "Entry fee must be greater than $0", "Entry fee cannot be more than $999.99"                                                               |
| `games`         | whole number, 1 to 99                             | yes      | `SQD-12`, D-175. "Games must be between 1 and 99"                                                                                                           |
| `cashRatio`     | number, 1.1 to 99.9, one decimal                  | yes      | `SQD-11`, D-175                                                                                                                                             |
| `bonusPins`     | object: division id to blank, or a whole 0 to 99  | no       | `SQD-13`, D-176. A missing key is `{}`. A blank or 0 saves no `SweeperDivision` row. A key that is not a division of the tournament is `409` (D-177)       |

## Edit fields

What `PATCH /v1/tournaments/{id}/squads/{sessionId}` and `/sweepers/{sessionId}` take (D-180 to D-185). The body holds only the fields to change, plus optional `confirmWarnings`. Every field sent gets the add check and message; a field left out is not rechecked, so a stored value that breaks a limit does not block an edit of something else (D-17). The body is strict: `complete`, `games` or `finalsRatio` on the wrong kind, and any unknown key are `400`, so an edit cannot reopen a session (`SQD-18`).

A squad takes `date`, `startingLane`, `numberOfLanes`, `maxPerPair`, `entryFee`, `finalsRatio`, `cashRatio`; a blank, `""`, or `null` fee or ratio clears the override (D-183). A sweeper takes `date`, `startingLane`, `numberOfLanes`, `maxPerPair`, `entryFee`, `games`, `cashRatio`, and `bonusPins`: a division id to a whole 0 to 99, only for the divisions to change; one left out is unchanged, and a blank or 0 deletes that row (D-184). A sweeper's fee, games, and cash ratio are never blank.

What decides whether a field may change. A warning appears only when the value really changes. The counts are for **this session only**: a score in another squad has no bearing (D-180). "Entries" are registered bowlers on the session, "assignments" are saved lane positions, "scores" are saved scores.

| Field                                                     | Free           | Asks the director to confirm                                      | Refused                                                          |
| --------------------------------------------------------- | -------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------- |
| `date`                                                    | No entries     | Entries exist (they planned around the time)                      | Outside the tournament dates; complete session or tournament     |
| `startingLane`, `numberOfLanes`                           | No assignments | Assignments exist and all still fit (recap sheets use the lanes)  | A saved lane falls outside the new range (D-182); complete       |
| `maxPerPair`                                              | No assignments | Assignments exist and all still fit                               | A pair holds more bowlers than the new max (D-182); complete     |
| `entryFee` (squad and sweeper)                            | No entries     | Entries exist (they keep what they paid)                          | Complete                                                         |
| `finalsRatio`, `cashRatio` (squad), `cashRatio` (sweeper) | No scores      | Scores exist (posted results change at once)                      | Complete                                                         |
| `games` (sweeper)                                         | No scores      |                                                                   | Scores exist; complete                                           |
| `bonusPins` (sweeper), each division                      | No scores      | Scores exist, for each pin that really changes                    | A division that is not the tournament's (`409`, D-177); complete |

A complete tournament refuses first, then a complete session (D-181). Lanes that pass lane 200 are a `400` (D-179), using the stored value for a lane field not sent. A seat letter is not rechecked, because stored letters show as stored (D-61). The counts are read just before one serializable transaction, so two edits of one session cannot interleave (D-184).

## Screens

- **Squads** (`/tournaments/{id}/squads`) and **Sweepers** (`/tournaments/{id}/sweepers`): a list of cards, reached from the "Squads" and "Sweepers" links in the tournament sidebar, which mark the current page. Loading, error with Try again, and empty states. Edit and Delete buttons on each card (`SQD-30`, `SQD-34`), no Complete button (it is in the session page header, D-195), and the date on each card links to the session's page (`LAN-15`, D-60).
- **New squad** (`/tournaments/{id}/squads/new`): reached from a "New squad" link beside the Squads heading, shown only to a user with `squads.write` and hidden on a complete tournament. The form has a date and time box limited to the tournament days, a Lanes group (starting lane, number of lanes, bowlers per pair, the last three starting with the latest squad's values), and a Fee and ratios group whose blank boxes show the tournament's values. Errors show under each box with a summary that moves focus to the first problem; a save returns to the Squads page with a "Squad created" toast. Loading and error states wait for the tournament settings and the squads list; a failed list leaves the lane boxes blank; a complete tournament shows "This tournament is complete" (D-167 to D-172).
- **New sweeper** (`/tournaments/{id}/sweepers/new`): reached from a "New sweeper" link beside the Sweepers heading, shown only to a user with `squads.write` and hidden on a complete tournament. The form has a date and time box limited to the tournament days, a Lanes group (the last three boxes start with the latest sweeper's values, D-178), an Entry and payout group (fee, games, cash ratio, all required and never filled in), and a Bonus pins per game group with a box for each division. Errors show under each box with a summary that moves focus to the first problem; a save returns to the Sweepers page with a "Sweeper created" toast. Loading and error states wait for the settings, the divisions, and the sweepers list; a failed sweepers list leaves the lane boxes blank; a complete tournament shows "This tournament is complete" (D-174 to D-178).

- **Edit squad** (`/tournaments/{id}/squads/{sessionId}/edit`) and **Edit sweeper** (`/tournaments/{id}/sweepers/{sessionId}/edit`): reached from the "Edit" link on a card (`SQD-30`). The add form filled with the stored values, with the limit, lock, and confirm lines under the boxes, the shared confirm dialog, and a "Squad saved" or "Sweeper saved" toast on return to the list (`SQD-27`, `SQD-28`). The sweeper form has a bonus-pins box for each division (`SQD-29`).
- **Delete squad** and **Delete sweeper**: a "Delete" button on each card opens the Cancel and Delete dialog (`SQD-34`). It is not a page; a delete returns to the same list with a toast.
- **Complete squad** and **Complete sweeper**: a button in the header of the session page (`/tournaments/{id}/squads/{sessionId}` and the sweeper twin) opens the Cancel and Complete dialog, then a toast (`SQD-38`, `SQD-39`). It is not a page.

## Local data

`npm run db:seed` adds three squads (one complete, one overriding fee and finals ratio, one with its own cash ratio and lane range) and two sweepers (one with pins on Open and Women; one with a NULL, a 0, and a Women row) to each of the four sample tournaments. Running it twice adds nothing. The mock server (`npm run dev:mocks`) pretends the second demo squad has 12 entries (so its date and fee ask to confirm, and delete is refused) and the first demo sweeper has scores (so games lock, the ratio and pins ask to confirm, and delete is refused). The other demo sweeper is complete, so none can be deleted; the e2e test adds a sweeper first. For completing, the mock pretends the second demo squad has 12 entries (3 with no scores, 1 short), so its dialog lists them and the toast says 3 bowlers got zeros; any other squad or sweeper shows no entries.
