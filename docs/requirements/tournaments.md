# Tournaments

Built on branches `landingPage`, `tournamentList`, `createTournament`, and `editTournament`. Migration source: [docs/migration/tournaments.md](../migration/tournaments.md).

The API reads and creates rows in the legacy `Tournaments` table in the MariaDB database through Prisma (D-26, D-30). Reading is public (0.2.0). Creating and editing need sign-in and `tournaments.write` (director and admin, D-97). Deleting and completing come in later runs.

## Fields

What the API returns for a tournament. Dates are `YYYY-MM-DD`, with no time zone.

| Field           | Type        | Required | Notes                         |
| --------------- | ----------- | -------- | ----------------------------- |
| `id`            | UUID        | yes      |                               |
| `name`          | text        | yes      |                               |
| `startDate`     | date        | yes      | First day                     |
| `endDate`       | date        | yes      | Last day                      |
| `entryFee`      | number, > 0 | yes      | Default fee for a squad entry |
| `bowlingCenter` | text        | yes      | Name of the venue             |

These are the vendor summary fields (D-24, D-09). The settings below are web only (D-126).

### Settings and create fields

What `POST /v1/tournaments` takes, with its limits (D-125), and what `GET /v1/tournaments/{id}/settings` returns.

| Field                   | Type                            | Required | Notes                                                            |
| ----------------------- | ------------------------------- | -------- | ---------------------------------------------------------------- |
| `name`                  | text, trimmed, 1 to 100         | yes      | Create only (summary field above)                                |
| `bowlingCenter`         | text, trimmed, 1 to 100         | yes      | Create only (summary field above)                                |
| `startDate`, `endDate`  | `YYYY-MM-DD`, any date          | yes      | End on or after start (`TRN-02`, D-124)                          |
| `entryFee`              | number, above 0, at most 999.99 | yes      | Two decimals                                                     |
| `games`                 | whole number, 1 to 99           | yes      | Games per qualifying squad                                       |
| `finalsRatio`           | number, above 1, at most 99.9   | yes      | One decimal. 1 in N advance                                      |
| `cashRatio`             | number, above 1, at most 99.9   | yes      | One decimal. 1 in N cash                                         |
| `superSweeperCashRatio` | number, 1 to 99.9               | yes      | One decimal. No default (D-122). A stored legacy 0 is read as is |

`Completed` is not an input: a new row stores false (D-119), and an edit never writes it (D-130).

### Editing a field (D-128, D-130)

What decides whether a field may change. A warning appears only when the value really changes. "Scores" means any saved score in the tournament, squad or sweeper; "sweeper scores" means any saved score in a sweeper.

| Field                      | Free              | Asks the director to confirm                         | Refused                                                                              |
| -------------------------- | ----------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `name`, `bowlingCenter`    | Always            |                                                      | Complete tournament                                                                  |
| `endDate`                  | Moving it later   |                                                      | A squad or sweeper falls after the new end day; complete tournament                  |
| `startDate`                | No registrations  | Registrations exist (ages are measured on this date) | A squad or sweeper falls before the new start day; scores exist; complete tournament |
| `entryFee`                 | No registrations  | Registrations exist (they keep what they paid)       | Complete tournament                                                                  |
| `games`                    | No scores         |                                                      | Scores exist; complete tournament                                                    |
| `finalsRatio`, `cashRatio` | No scores         | Scores exist (posted results change at once)         | Complete tournament                                                                  |
| `superSweeperCashRatio`    | No sweeper scores | Sweeper scores exist                                 | Complete tournament                                                                  |

A complete tournament is frozen: every field is refused, name and center included (D-130). Nothing in the new app sets the flag yet; the Complete action is built with Complete squad and Complete sweeper.

How a stored row becomes those fields:

| Column          | Field                  | Notes                                                       |
| --------------- | ---------------------- | ----------------------------------------------------------- |
| `Id`            | `id`                   | `char(36)`                                                  |
| `Name`          | `name`                 |                                                             |
| `Start`, `End`  | `startDate`, `endDate` | `datetime(6)` at midnight, read as UTC, cut to `YYYY-MM-DD` |
| `EntryFee`      | `entryFee`             | `decimal(5,2)` to a number                                  |
| `BowlingCenter` | `bowlingCenter`        |                                                             |

`Games`, the three ratios, and `SuperSweperCashRatio` are read by the settings route (`TRN-21`). `Completed` is written false on create. The settings route sends it, and the edit rules freeze a tournament that has it set (D-130, D-131).

## API

| Route                                | Response                                                                                              | Errors                                                                                                                              | Vendor-visible                     |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `GET /v1/tournaments`                | `200 { tournaments: [{ id, name, startDate, endDate, entryFee, bowlingCenter }] }`                    | `503` database down                                                                                                                 | Yes (`API-03`)                     |
| `POST /v1/tournaments`               | `201 { tournament: { …summary…, games, finalsRatio, cashRatio, superSweeperCashRatio } }`, `Location` | `400 { message, errors }`; `401`; `403`; `409 { message, errors: { name } }`; `503`                                                 | No (web only, `tournaments.write`) |
| `GET /v1/tournaments/{id}/settings`  | `200 { settings: { games, finalsRatio, cashRatio, superSweeperCashRatio, completed } }`               | `400`; `404 { message: "Tournament not found" }`; `500` bad stored row; `503`                                                       | No (web only, public)              |
| `PATCH /v1/tournaments/{id}`         | `200 { tournament: { …summary…, games, finalsRatio, cashRatio, superSweeperCashRatio } }`             | `400 { message, errors }`; `401`; `403`; `404`; `409 { message, errors }` (refused) or `409 { message, warnings }` (confirm); `503` | No (web only, `tournaments.write`) |
| `GET /v1/tournaments/{id}/edit-info` | `200 { editInfo: { registrationCount, hasScores, hasSweeperScores } }`                                | `400`; `401`; `403`; `404`; `503`                                                                                                   | No (web only, `tournaments.write`) |
| `GET /v1/tournaments/{id}`           | `200 { tournament: { …same fields… } }`                                                               | `400` not a UUID; `404 { message: "Tournament not found" }`; `500` bad stored row; `503` database down                              | Yes (`API-04`)                     |

The shapes are fixed by D-09. The API's `types.ts` and the web app's `types.ts` carry the same fields; change both together, and only after a vendor change doc. The old demo route `GET /tournaments` is removed. The 503 is new, and appears only while the database is down. `GET /ready` (`TRN-16`) is not part of the vendor contract. `POST /v1/tournaments`, `PATCH /v1/tournaments/{id}`, `edit-info`, and the settings route are not either: the legacy API has no such routes, so the vendor sees no change (D-09).

## Screens

- **Home** (`/`): the current tournament card, and a link to all tournaments. The Check API button is gone (D-29). See TRN-14.
- **Tournaments** (`/tournaments`): the two groups. Each row is a card with a badge (current and upcoming only), the name as a link, then dates, center, and fee. Loading, error with Try again, and empty states. See TRN-13. A "New tournament" link sits beside the heading for users with `tournaments.write` (`TRN-22`).
